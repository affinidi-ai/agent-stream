# Example Configuration

Reference copies of every configuration file Agent Stream reads, plus the seed data some of
them point at.

The binary does not load anything from this directory. A running instance reads
`config.toml` from the path given by `--config` and every other file from the locations that
file names. For a local source build that is `envs/local/config/`, which `make run-debug`
prepares through [`scripts/_prepare.sh`](../../scripts/_prepare.sh): it generates
`config.toml` with `agent-stream --generate-bootstrap` and copies the examples it needs.
`make config-docker` prepares `envs/docker/config/` the same way, except that `config.toml` is
generated by running the `agent-stream:local` image, so its paths are container paths under
`/app`. Existing copies are never overwritten. One file here is also compiled in:
`rejection_categories.example.json` is embedded as the fallback taxonomy.

For what each file controls and the effect of its fields, see
[`docs/CONFIGURATION_REFERENCE.md`](../../docs/CONFIGURATION_REFERENCE.md). For what applies
without a restart, see [`docs/CONFIGURATION_RELOAD.md`](../../docs/CONFIGURATION_RELOAD.md).

## Files Agent Stream loads

Each target is named from `[config_files]` in `config.toml` and resolves against the
directory holding `config.toml`.

| Example | Copy to | Controls | Copied by `make run-debug` and `make config-docker` |
| --- | --- | --- | --- |
| [`config.example.toml`](config.example.toml) | `config.toml` | Bootstrap: file and storage locations, TLS, encryption at rest, server mode, appliance-wide Surface defaults. The entry point that names every other file. | No; generated with `--generate-bootstrap` |
| [`agent-stream.example.json`](agent-stream.example.json) | `agent-stream.json` | Listeners, route mounting, LLM route prefixes, DID domain, WebAuthn, CORS, Terms, integration types, secret read-back (`secrets.reveal_values`, `true`), catalog refresh (`llm_catalog.refresh_url` empty, so the action is off; `allow_insecure_source` `false`), drift runner. Required. | Yes, with ports and domain filled in (`localhost` and `https://localhost:8443` for Docker) |
| [`metrics.example.json`](metrics.example.json) | `metrics.json` | OpenTelemetry, CloudWatch, retention, host metrics. OpenTelemetry and CloudWatch are off; the CloudWatch namespace is `AgentStream`. | Yes |
| [`rbac.example.json`](rbac.example.json) | `rbac.json` | The minimum role each management permission requires. Every role it lists matches the built-in default; the permissions it omits keep their defaults, so copying it changes nothing. | Yes |
| [`limits.example.json`](limits.example.json) | `limits.json` | Ceilings on how many records of each kind may exist. Its values are small (for example 5 LLM Surfaces, 3 Teams, 1 gateway); without the file nothing is limited. | No |
| [`llm.example.json`](llm.example.json) | `llm.json` | Seed for the Model catalog. Copied once into `storage_paths.llm_configuration` on first start; the stored copy is authoritative afterwards. | Yes |
| [`saml.example.json`](saml.example.json) | `saml.json` | SAML identity provider. Read only when `auth_mode = "saml"`. | Yes |
| [`oidc.example.json`](oidc.example.json) | `oidc.json` | OpenID provider, client and role mapping. Read only when `auth_mode = "oidc"`. | No |
| [`prompt-guard.example.json`](prompt-guard.example.json) | `prompt-guard.json` | Built-in Prompt Guard pattern definitions. | Yes |
| [`rejection_categories.example.json`](rejection_categories.example.json) | `rejection_categories.json` | Rejection-reason taxonomy. Optional: the same content is compiled in and used when the file is absent or invalid. | No |
| [`audio_streams.example.json`](audio_streams.example.json) | `audio_streams.json` | Catalog of voice filler clips for the realtime relay. | No |
| [`surface_templates/`](surface_templates/) | the directory named by `surface_templates_dir` | Built-in Surface templates seeded into the template store at startup. Has its own [README](surface_templates/README.md). | Yes |

[`marketplace-models.example.json`](marketplace-models.example.json) (copied to
`marketplace-models.json`) configures marketplace support, which this documentation does not
cover.

## Seed data

These are not configuration files. Agent Stream reads them at startup from a storage location
that `config.toml` names in `[storage_paths]`.

| Example | Copy to | Notes | Copied by `make run-debug` and `make config-docker` |
| --- | --- | --- | --- |
| [`defaults/default_members/`](defaults/default_members/) | the directory named by `storage_paths.default_members` (default `defaults/default_members`, beside `config.toml`) | The built-in `anonymous` and `sandbox` Members, created in the Member store if absent. | Yes |
| [`defaults/default_teams/`](defaults/default_teams/) | the directory named by `storage_paths.default_teams` (default `defaults/default_teams`) | The built-in `anonymous` and `sandbox` Teams, created in the Team store if absent. | Yes |
| [`audio_streams/`](audio_streams/) | the directory named by `storage_paths.audio_streams` (default `../_storage/audio_streams`) | The WAV clips (PCM16, 24 kHz, mono) that `audio_streams.json` catalogs by file name. | No |

## Secrets and placeholders

Agent Stream does not substitute placeholders. Tokens such as `YOUR_DOMAIN` in
`agent-stream.example.json`, `$AZURE_TENANT` and `XXXXXXXX` in `saml.example.json`, and
`YOUR_PROVIDER`, `YOUR_CLIENT_ID` and `YOUR_ORG_ID` in `oidc.example.json`, are literal text until you replace them. (`$VARIABLE` in the integration pattern description and
`$SURFACE_NAME`-style tokens in Surface templates are filled at run time by those features,
not by configuration loading.)

Where a setting accepts a secret reference, these schemes resolve at startup:

| Scheme | Resolves to | Accepted by |
| --- | --- | --- |
| `env://NAME` | An environment variable | `backup_encryption_key`, `legacy_backup_encryption_keys`, `oidc.json` `client_secret`, and the `AS_IDENTITY_HASH_PEPPER` and `AS_PRINCIPAL_KEY_SECRET` values |
| `file://PATH` | A file's contents | The same settings |
| `aws_secrets://NAME` | An AWS Secrets Manager secret | `oidc.json` `client_secret`, and `AS_IDENTITY_HASH_PEPPER` and `AS_PRINCIPAL_KEY_SECRET` |
| `aws_parameter_store://NAME` | An AWS Systems Manager parameter | `oidc.json` `client_secret`, and `AS_IDENTITY_HASH_PEPPER` and `AS_PRINCIPAL_KEY_SECRET` |
| `string://VALUE` | A literal value | `AS_IDENTITY_HASH_PEPPER` and `AS_PRINCIPAL_KEY_SECRET` only |

A value with no scheme is taken literally. `config.example.toml` sets
`backup_encryption_key = "env://AS_BACKUP_ENCRYPTION_KEY"`; startup fails unless that
variable holds a 64-character hex key. Other fields, such as `saml.json`
`graph_api.client_secret`, accept only a literal. See
[Secret references](../../docs/CONFIGURATION_REFERENCE.md#secret-references).

The examples here are the only copies meant to be committed. `envs/` and `_storage` are
ignored entirely, and [`.gitignore`](../../.gitignore) also ignores `config.toml`, `saml.json`,
`llm.json`, `metrics.json` and `rbac.json` anywhere in the tree.
`agent-stream.json`, `limits.json`, `oidc.json`, `prompt-guard.json`, `rejection_categories.json`
and `audio_streams.json` are not ignored outside `envs/`, so keep a deployment's copies out of the
repository.
